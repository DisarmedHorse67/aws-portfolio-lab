# ADR-004: Use us-east-1 as the primary Region

Status: proposed
Date: 2026-10-29

Context: The project needs one primary Region for all workloads. CloudFront
only accepts ACM certificates issued in us-east-1, and Identity Center's
home Region cannot be changed after it is set.

Options:
- us-east-1 (N. Virginia): required for CloudFront certificates, widest
  service availability, the Region AWS uses for most pricing examples;
  it has had large outages in the past.
- us-east-2 (Ohio): similar prices and fewer outages historically, but a
  us-east-1 provider is still needed for the certificate.
- A Region closer to me: lower latency for direct requests, but fewer
  services in some Regions, and CloudFront already serves visitors from
  nearby edge locations.

Decision: Use us-east-1 for everything. It avoids splitting resources
across Regions for the certificate, and latency does not matter because
visitors are served by CloudFront.

Consequences:
- Cost: no extra cost; the SCP denies all other Regions, with exceptions
  for global services.
- Risk: a regional outage affects the site; the documented multi-region
  failover design covers how this would be handled.
- Simplicity: one Region means one set of provider settings in Terraform.
