# ADR-005: Develop inside a dev container

Status: accepted
Date: 2026-10-29

Context: I work on this project from two laptops. Tool versions (Terraform,
AWS CLI, Hugo, gitleaks, pre-commit) must be identical on both and match
what the pipeline uses, otherwise plans and builds differ between machines.

Options:
- Install tools directly on each laptop: no extra layer; versions drift
  between machines and the setup is undocumented.
- Dev container committed to the repo: identical environment on both
  laptops, versions pinned and visible to reviewers; needs Docker and a
  first build.
- Cloud development environment (for example GitHub Codespaces): no local
  setup; usage limits and costs, and AWS access happens from a hosted
  machine.

Decision: Use a dev container defined in `.devcontainer/`, with pinned
tool versions, as the standard environment on both laptops.

Consequences:
- Cost: none beyond local resources; the first build takes time.
- Credentials: AWS access uses SSO login from inside the container
  (`aws sso login --use-device-code` works without a browser there);
  no keys are stored in the image or the repo. If `~/.aws` is mounted from
  the host, the container can use the cached SSO tokens, which is accepted
  and documented.
- Consistency: the pipeline reads the same pinned versions so local and CI
  results match.
- Risk: unpinned versions can drift; versions are set in one place and
  reviewed when updated.
