# ADR-008: Use Python for Lambda functions and automation

Status: proposed
Date: 2026-10-29

Context: The backend, the lab reaper and the remediation function all need
code. One language keeps the project consistent.

Options:
- Python: readable, widely used in security automation, boto3 is available
  in the Lambda runtime.
- Node.js (TypeScript): natural fit with a JavaScript front end; less
  common in SOC scripting.
- Go: fast and small binaries; more setup and less relevant to my goals.

Decision: Use Python for all Lambda functions and scripts.

Consequences:
- Cost: none; traffic is low enough that cold starts do not matter.
- Maintenance: Lambda runtimes are deprecated on a schedule, so the runtime
  version is pinned in Terraform and reviewed when AWS announces changes.
- Packaging: extra libraries must be bundled with the function; the plan
  keeps dependencies to a minimum.
